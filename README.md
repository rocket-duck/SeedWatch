# SeedWatch

SeedWatch следит за обновлениями раздач через Prowlarr, проверяет недостающие эпизоды в Sonarr и отправляет торренты в qBittorrent. Поддерживает RuTracker, Kinozal, AniLiberty и другие индексеры, настроенные в Prowlarr, а также страницы сериалов AniStar — напрямую, без Prowlarr.

Сервис работает с собственным WebUI и не требует доступа к медиабиблиотеке или папке загрузок. Все взаимодействия выполняются через API.

## Возможности

- Мониторинг ссылок на раздачи с любых индексеров Prowlarr.
- Прямой мониторинг страниц сериалов AniStar (anistar.org, astar.bz) — без Prowlarr.
- Режим догона для AniStar: если связанный сериал Sonarr пуст, при добавлении скачиваются все вышедшие серии.
- Выбор озвучки AniStar по приоритету: многоголосая > несколько дикторов > одноголосая.
- Поддержка паков AniStar: один торрент может покрывать диапазон серий.
- Метка источника раздачи (индексер или AniStar) в списке раздач.
- Индивидуальный интервал проверки от 1 до 365 дней.
- Первая проверка сразу после добавления раздачи.
- Выбор связанного сериала из списка Sonarr.
- Проверка эпизодов с `hasFile` в Sonarr, включая абсолютную нумерацию аниме.
- Отключение уже скачанных видеофайлов через приоритеты qBittorrent.
- Автоматический fallback на полную загрузку, если файлы нельзя надёжно сопоставить с сериями.
- Настройка Prowlarr, Sonarr и qBittorrent через WebUI без перезапуска.
- Авторизация в qBittorrent по логину и паролю или API key.
- История срабатываний, пауза и ручная проверка раздач.
- Хранение настроек и состояния в SQLite.

## Как это работает

```text
Ссылка на раздачу
       ↓
Prowlarr ищет обновлённый релиз
       ↓
Sonarr сообщает, какие эпизоды уже имеют файлы
       ↓
SeedWatch отправляет торрент через Prowlarr
       ↓
qBittorrent получает приоритеты только для недостающих файлов
```

Для ссылок на AniStar схема другая, Prowlarr не участвует:

```text
Страница сериала AniStar
       ↓
SeedWatch сам читает страницу и выбирает торренты
(недостающие серии, одиночные или паки, приоритет озвучки)
       ↓
qBittorrent получает торренты напрямую
```

При добавлении раздачи проверка выполняется немедленно. Следующие проверки происходят через заданное число дней.

Если сериал в Sonarr не выбран, SeedWatch отправляет текущую раздачу при добавлении и новые эпизоды при последующих обновлениях, без проверки медиабиблиотеки и файловой дельты.

## Требования

- Docker.
- Prowlarr с настроенными индексерами (не нужен для ссылок на AniStar).
- qBittorrent, подключённый к Prowlarr как download client.
- Sonarr, если нужны выбор сериала, проверка `hasFile` и файловая дельта.
- Для авторизации по API key — qBittorrent 5.2 или новее. Для более старых версий используйте логин и пароль.

## Установка на Unraid

Добавьте контейнер со следующими параметрами:

| Параметр | Значение |
|---|---|
| Repository | `ghcr.io/rocket-duck/seedwatch:latest` |
| Container Port | `8787` |
| Host Port | `8787` или другой свободный порт |
| Container Path | `/data` |
| Host Path | `/mnt/user/appdata/seedwatch` |
| Access Mode | `Read/Write` |

Переменные Docker для Prowlarr, Sonarr и qBittorrent указывать не нужно.

После запуска откройте:

```text
http://IP_UNRAID:8787
```

Доступ к `/mnt/user/data` и папке загрузок SeedWatch не требуется.
## Первоначальная настройка

Откройте **Настройки** в правом верхнем углу WebUI.

### Prowlarr

- **URL**: например, `http://192.168.1.10:9696`.
- **API key**: находится в Prowlarr → **Settings → General → API Key**.

Убедитесь, что qBittorrent добавлен в Prowlarr → **Settings → Download Clients**.

### Sonarr

- **URL**: например, `http://192.168.1.10:8989`.
- **API key**: находится в Sonarr → **Settings → General → API Key**.

Sonarr нужен только для проверки библиотеки и файловой дельты. Без него базовый мониторинг продолжит работать.

### qBittorrent

- **URL WebUI**: например, `http://192.168.1.10:8080`.
- **Логин и пароль**: учётные данные WebUI qBittorrent.
- **API key**: альтернатива для qBittorrent 5.2+. Ключ создаётся в **Preferences → WebUI → API Key**.

URL qBittorrent должен указывать на тот же клиент, в который Prowlarr отправляет раздачи.

Настройки применяются сразу после сохранения. Состояние подключений Prowlarr, Sonarr и qBittorrent отображается в верхней панели. URL можно вводить без схемы: адрес `192.168.1.10:9696` автоматически преобразуется в `http://192.168.1.10:9696`.

Секреты не отображаются в открытом виде и не возвращаются через API. Звёздочки означают, что значение сохранено. Пустое поле секрета сохраняет прежнее значение; для замены введите новый ключ или пароль.

## Добавление раздачи

1. Скопируйте ссылку на страницу раздачи с трекера.
2. Вставьте её в поле **Ссылка на раздачу**.
3. Укажите интервал проверки в днях.
4. При необходимости задайте короткий поисковый запрос. Он полезен, если страница требует авторизации или полное название плохо находится через Prowlarr. Для ссылок на AniStar поисковый запрос не нужен.
5. Выберите сериал Sonarr, если нужна проверка недостающих эпизодов и файловая дельта.
6. Нажмите **Добавить и проверить**.

SeedWatch сопоставляет ссылку с `infoUrl` и `guid` результатов Prowlarr. Для RuTracker дополнительно поддерживается идентификатор темы `t=`.

Если трекер не позволяет прочитать страницу раздачи, например отвечает `403 Forbidden`, при выбранном сериале SeedWatch автоматически ищет через Prowlarr по его названию. Без привязки к Sonarr укажите поисковый запрос вручную.

Ссылка на страницу сериала AniStar (anistar.org или astar.bz) распознаётся автоматически по адресу: такая страница читается напрямую, Prowlarr и поисковый запрос для неё не нужны. Если связанный сериал Sonarr ещё не содержит эпизодов, при добавлении SeedWatch сразу скачает все вышедшие серии (режим догона) — для этого должен быть настроен qBittorrent. Режим догона срабатывает только в момент добавления: привязка сериала Sonarr к уже существующей раздаче AniStar не догружает серии, уже опубликованные на странице. При повторных проверках докачиваются только новые серии, с учётом приоритета озвучки и поддержкой паков.

Если индексеру нужен FlareSolverr, подключите его в настройках соответствующего индексера в Prowlarr. Страницы, которые SeedWatch читает напрямую (AniStar и страницы раздач для получения названия), при указанном в настройках SeedWatch URL FlareSolverr запрашиваются через него.

## Файловая дельта

При выбранном сериале Sonarr SeedWatch вычисляет недостающие эпизоды по `hasFile`. После добавления торрента сервис ждёт метаданные qBittorrent и анализирует имена видеофайлов.

- Файлы, содержащие только уже скачанные серии, получают `priority=0`.
- Файлы с недостающими сериями остаются в закачке.
- Если хотя бы один видеофайл неоднозначен или файл нужной серии не найден, приоритеты не изменяются и торрент скачивается полностью.
- Если qBittorrent недоступен или новый торрент не найден, также используется полная загрузка.

Приоритеты применяются после получения метаданных, поэтому qBittorrent может начать скачивание до их выставления. Результат проверки и причина fallback записываются в историю раздачи.

## Запуск через Docker Compose

Для локального запуска из исходников:

```bash
git clone https://github.com/rocket-duck/SeedWatch.git
cd SeedWatch
docker compose up -d --build
```

WebUI будет доступен на `http://localhost:8787`. Подключения настраиваются через WebUI.

Для обновления до опубликованного образа:

```bash
docker compose pull
docker compose up -d
```

## Данные и безопасность

В `/data/monitor.db` хранятся раздачи, расписания, история и настройки подключений, включая секреты. Сохраняйте эту папку при обновлении контейнера и ограничьте доступ к ней.

В SeedWatch пока нет собственной аутентификации WebUI. Не публикуйте сервис в интернет без reverse proxy с авторизацией и не открывайте доступ к нему из недоверенной сети.

## Разработка

Локальный запуск:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload --port 8787
```

Запуск тестов:

```bash
.venv/bin/pytest -q
```

Тесты используют локальные имитации Prowlarr, Sonarr и qBittorrent. Настоящие сервисы, сеть и API‑ключи не нужны.

Покрываются:

- разбор номеров эпизодов и ссылок разных трекеров;
- парсинг страниц AniStar, приоритеты озвучки и паки;
- сохранение и маскирование настроек;
- авторизация qBittorrent по API key и логину/паролю;
- немедленная загрузка и последующий поллинг;
- проверка `hasFile` в Sonarr;
- файловая дельта и полный fallback;
- защита от повторной отправки.

GitHub Actions запускает тесты перед каждой публикацией Docker‑образа. Если тесты не проходят, образ в GHCR не обновляется.
